# Stops on RV32

[中文](../../zh/course/rv32.md)

[Question list](../course.md)

Boot is still `labs/rv32/qemu/launch.sh`. The UART is that terminal. Press F5, choose **RV32**, stop at `_start` in `entry.S`, then set breakpoints on functions. Addresses belong to the build you just made.

This column's nameplate is M-mode, [`satp`](../rv32_instructions.md#satp), and U-mode. See the [mechanism pictures](../mech.md).

## What the UART shows

```text
rv32
hart 0
uart 0x10000000
timebase 10000000
sv32 on
disk 0x10008000
$ ls
ls
sh
echo
sleep
$ echo hello
hello
$ nosuch
not found
$ sleep
sleep: ms
$ sleep 10
$ exit
```

`sleep 10` waits 10ms, which looks instant on the terminal. `sleep 1000` makes the pause visible. `uart`, `timebase`, and `disk` come from the device tree on that boot. QEMU 10.2.1 printed the numbers above.

`fork` in `exec.c` calls `copy_page`. `exec` loads the program and calls `swtch`, and the child starts at its own `_start`. `exit` calls `swtch` back to the shell. The pages used on the way back are the ones `fork` saved. The kernel does not read `sh` from the disk again. `current_name` is the program's name while that child runs, and `sh` again at the prompt.

## Where to stop

### Reset {#boot}

F5 stops at `_start`. `a0` is the hart, `a1` is the device tree. Continue, and the UART prints the machine lines, then `$`.

### mret {#mode}

Break on `mret` in `entry.S`. One step later the CPU is in S-mode.

### satp {#pages}

Break in `vm_on` in `vm.c`, on the write to `satp`. Step past it. The UART then prints `sv32 on`, and the prompt follows.

### U-mode {#privilege}

After `$` appears, break on `syscall` in `exec.c`. Press Enter. The mode that trapped was U-mode. The call number is in `a7`.

### scause {#timer}

`$` is on screen and no key has been pressed. Break on `trap_handler` in `traps.c`. `scause` is `0x80000005`: the high bit is 1 and the low bits are 5. `current_name` is `sh`. Continue twice. The handler runs twice more. Each time `stimecmp` is one interval later. That interval is `timebase / 100`, 10ms on this board.

### ecall {#ecall}

Break on `syscall`. Type `echo hello`. The shell's `exec` enters with `a7` equal to 3. `echo` writes the UART with `a7` equal to 1. The UART prints `hello`.

### swtch {#switch}

Break on `swtch` in `swtch.S`. Type `echo hello` again. The first stop saved the shell and resumes `echo` at `_start`. `echo` exiting stops here again, back in the shell at its next read.

### copy_page {#copy}

Break on `copy_page` in `mem.c`. Type `ls` again. The function runs once. The source is the shell's stack page, the destination is the child's stack page, 1024 words, 4096 bytes. The next line at `$` still reads.

Type `nosuch`. The UART prints `not found`. Neither `swtch` nor `copy_page` runs.

Break on `trap_handler` and type `sleep 10`. While it waits, `current_name` is `sleep` and `scause` is still the supervisor timer. When the wait ends, `swtch` returns to the shell, and the UART then prints `$`.

### Byte {#byte}

After `$`, break on `uart_getc` in `uart.c`. Type one letter. UART base plus 5 is the line status register. When bit 0 is 1, the return value is that byte. Receive is not an interrupt: the timer wakes the wait, and the next check reads the register.

### Line {#line}

Break on `read_line` in `uart.c`. Type `echo hello`. The letters collect here, and the whole line goes to the shell after Enter.

### Name {#name}

Break on `lookup` in `fs.c`. Type `echo hello` again. The argument is `echo`. After it returns, `name_block` is that file's sector number.

### Block {#block}

Break on `bread` in `fs.c`. The first `echo hello` enters `virtio_read`. The same command again returns the cached block from `bread` and does not enter `virtio_read`.

### Disk done {#disk}

Break on `trap_handler` in `traps.c` and type a command whose program is not loaded yet, such as the first `echo hello`. `scause` is `0x80000009`. The handler is `virtio_isr` in `virtio.c`: it claims the interrupt at the PLIC and acknowledges virtio. A second `echo hello` does not enter it again. That block is still in the `bread` cache.
