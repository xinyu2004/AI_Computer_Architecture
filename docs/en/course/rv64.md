# Register width on RV64

[中文](../../zh/course/rv64.md)

[Question list](../course.md)

RV64 answers the same questions as [RV32](rv32.md). The programs are still `sh`, `ls`, `echo`, and `sleep`. The table on the course page stays 80386, RV32, and ARM.

```sh
labs/rv64/qemu/launch.sh
```

That script builds `src/rv64` with `-march=rv64gc -mabi=lp64` and boots `qemu-system-riscv64 -machine virt -cpu rv64 -bios none`. The UART prints `rv64`, then `sv39 on`, then `$`. Press F5 and choose **RV64** to stop at `_start`. Linux 0.11, RV32, and RV64 listen on `127.0.0.1:1234`. Start one at a time.

Three stops change with the register width.

Break in `vm_on` in `vm.c`, on the write to `satp`. The mode field, bits 63:60, is 8. That is Sv39: the table has three levels. Step past the write. The UART prints `sv39 on`.

Break on `trap_handler` in `traps.c` while `$` is on screen and no key has been pressed. `scause` is `0x8000000000000005`. The interrupt bit is bit 63, and the low bits are still 5. An external interrupt is `0x8000000000000009`. `ecall` from U-mode is still 8. `stimecmp` is the one register `0x14d`.

Break on `swtch` in `swtch.S` and type `echo hello`. Each saved register is 8 bytes. Break on `copy_page` in `mem.c` and type `ls`. One 4KiB page moves as 512 stores of 8 bytes.
