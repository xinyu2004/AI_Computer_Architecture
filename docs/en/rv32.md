# RV32 on the virt board

[中文](../zh/rv32.md)

This is the first machine of step 5. `src/linux-0.11/` stays the 80386 kernel. `src/rv32/` is a separate kernel. It turns page tables on, prints the machine lines, and leaves a shell. The programs on the disk are `ls`, `echo`, and `sleep`. The questions are in [the course](course.md). The stops on this machine are in [the RV32 pass](course/rv32.md).

Bochs and the gem5 x86 run are unchanged. This kernel is started on its own:

```bash
labs/rv32/qemu/launch.sh
```

The script builds `src/rv32/kernel.elf` and `sh`, `ls`, `echo`, and `sleep`, writes `images/rv32.img`, and boots with `qemu-system-riscv32 -machine virt -cpu rv32 -bios none`. The console is the board's UART. `help` lists the programs on the disk. `exit` shuts the machine down. Press F5 and choose **RV32** to stop at `_start` in `entry.S`, the kernel's first instruction. The UART output is in the terminal of that task. **Linux 0.11** in the same menu is still the 80386 session, and `labs/i386/qemu/launch.sh` still opens its VGA window. Linux 0.11, RV32, and RV64 listen on `127.0.0.1:1234`. Start one at a time.

## What the run prints

Boot prints the machine lines, then the shell prompt. `$ ` and the command list come from `src/user/sh.c`. The machine lines come from `main.c`, and `disk` from the virtio device found at boot:

```text
rv32
hart 0
uart 0x10000000
timebase 10000000
sv32 on
disk 0x10008000
$ ls
ls
sh
echo
sleep
$ echo hello
hello
$ sleep 10
$ exit
```

`uart`, `timebase`, and `disk` are the values read from the device tree on this boot. QEMU 10.2.1 produced the numbers above. A later QEMU can place the UART somewhere else; the kernel follows the tree it was given.

`images/rv32.img` holds `ls`, `sh`, `echo`, and `sleep`. Those are RV32 ELF programs linked at `0x10000`. The kernel loads `sh` and leaves that shell in place. `fork` copies one stack page, `exec` switches to the program you typed, and `exit` switches back. The 80386 disk remains `rootfs/hdc-0.11.img`. The kernel reads one line from the UART and echoes it.

The register-save in `swtch` has the same shape as [xv6-riscv](https://github.com/mit-pdos/xv6-riscv): `ra`, `sp`, and `s0` through `s11`. xv6 is a 64-bit kernel and uses a fixed UART address. This kernel is RV32 and reads the UART from the device tree.

## The board

`virt` is QEMU's RISC-V machine, not a chip you can buy. The width is the emulator binary plus `-cpu rv32`. That CPU is RV32GC. This kernel is integer code, so it is compiled `-march=rv32gc -mabi=ilp32`.

The board description is [QEMU's virt page](https://www.qemu.org/docs/master/system/riscv/virt.html). The CPU list is on [the RISC-V target page](https://www.qemu.org/docs/master/system/target-riscv.html).

RAM on this board starts at `0x80000000`, and the kernel is linked there. QEMU's reset vector jumps to `_start` in M-mode with the hart id in `a0` and the device tree in `a1`. `fdt.c` walks that tree. The UART is the node whose `compatible` string is `ns16550a`. On this board the `soc` bus has an empty `ranges` property, so the `reg` address is the physical address. The timer frequency is the `timebase-frequency` property. Power-off is a store to the `sifive,test` node.

## The five jobs

| Job | Where | What changes compared with the 80386 kernel |
| --- | --- | --- |
| Boot | `entry.S`, `main.c` | `_start` runs in M-mode, then `mret` enters S-mode. There is no firmware and no boot sector. |
| Page tables | `vm.c` | Sv32, two levels, 4KiB pages. `satp` names the root table. There is no GDT. |
| Timer | `traps.c` | `stimecmp` is written before the prompt, and again on every tick. The interrupt is supervisor cause 5. There is no 8259. |
| Task switch | `swtch.S` | `exec` saves the shell and enters the child. `exit` switches back. There is no TSS. |
| Copy one page | `mem.c` | `copy_page` in `fork` copies 1024 words, 4KiB, the same size as on the 80386. |

The last five questions are in [the course](course.md): `uart_getc` takes one byte, `read_line` collects a line, `lookup` matches a name to a sector, `bread` keeps that block, and `virtio_isr` claims the interrupt when the disk finishes.

Instruction names that do not say what they do are on [one page](rv32_instructions.md). The 80386 names, with the rows that belong only to that CPU or to the PC, are on [the 80386 page](i386_instructions.md).

Sv32, `mret`, PMP, and `stimecmp` are in the [RISC-V privileged specification](https://github.com/riscv/riscv-isa-manual).
