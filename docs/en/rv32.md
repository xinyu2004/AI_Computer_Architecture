# RV32 on the virt board

[中文](../zh/rv32.md)

This is the first machine of step 5. `src/linux-0.11/` stays the 80386 kernel. `src/rv32/` is a separate kernel that does the same five jobs: boot, page tables, one timer interrupt, a task switch, and a copy of one 4KiB page. It has no file system, no tty, and no disk.

Pressing F5 still starts **Linux 0.11**. Bochs and the gem5 x86 run are unchanged. This kernel is started on its own:

```bash
labs/rv32/launch.sh
```

The script builds `src/rv32/kernel.elf` and boots it with `qemu-system-riscv32 -machine virt -cpu rv32`. The console is the board's UART. `labs/qemu/launch.sh` still opens the VGA window for the 80386 kernel.

## What the run prints

OpenSBI prints its banner first. Two lines in that banner are the handoff: `Domain0 Next Address : 0x80400000` and `Domain0 Next Mode : S-mode`. The kernel then prints:

```text
rv32
hart 0
uart 0x10000000
timebase 10000000
sv32 on
timer
task 1
copy_page 4096
task 0
```

`uart` and `timebase` are the values read from the device tree on this boot. QEMU 10.2.1 with OpenSBI 1.8 produced the numbers above. A later QEMU can place the UART somewhere else; the kernel follows the tree it was given.

The register-save in `swtch` has the same shape as [xv6-riscv](https://github.com/mit-pdos/xv6-riscv): `ra`, `sp`, and `s0` through `s11`. xv6 is a 64-bit kernel and uses a fixed UART address. This kernel is RV32 and reads the UART from the device tree.

## The board

`virt` is QEMU's RISC-V machine, not a chip you can buy. The width is the emulator binary plus `-cpu rv32`. That CPU is RV32GC. This kernel is integer code, so it is compiled `-march=rv32gc -mabi=ilp32`.

The board description is [QEMU's virt page](https://www.qemu.org/docs/master/system/riscv/virt.html). The CPU list is on [the RISC-V target page](https://www.qemu.org/docs/master/system/target-riscv.html).

QEMU loads OpenSBI at `0x80000000` and this kernel at `0x80400000`. That address is the firmware handoff for `-kernel` on the 32-bit virt machine. Device addresses are not taken from it. OpenSBI passes the device tree in `a1`, and `fdt.c` walks it. The UART is the node whose `compatible` string is `ns16550a`. On this board the `soc` bus has an empty `ranges` property, so the `reg` address is the physical address. The timer frequency is the `timebase-frequency` property.

## The five jobs

| Job | Where | What changes compared with the 80386 kernel |
| --- | --- | --- |
| Boot | `entry.S`, `main.c` | OpenSBI is already in M-mode. The kernel starts in S-mode. There is no BIOS and no boot sector. |
| Page tables | `vm.c` | Sv32, two levels, 4KiB pages. `satp` names the root table. There is no GDT. |
| Timer | `traps.c`, `sbi.c` | `ecall` asks OpenSBI to set the deadline. The interrupt is supervisor cause 5. There is no 8259. |
| Task switch | `swtch.S` | Software stores `ra`, `sp`, and `s0`–`s11`, then loads the other task. There is no TSS. |
| Copy one page | `main.c` | A loop of 1024 words, 4KiB, the same size as `copy_page` on the 80386. |

Instruction names that do not say what they do are on [one page](rv32_instructions.md). The 80386 names, with the rows that belong only to that CPU or to the PC, are on [the 80386 page](i386_instructions.md).

The timer call and the shutdown call are the SBI extensions TIME and SRST. The text of those calls is in the [SBI specification](https://github.com/riscv-non-isa/riscv-sbi-doc). Sv32 is in the [RISC-V privileged specification](https://github.com/riscv/riscv-isa-manual).
